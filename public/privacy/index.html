Privacy policy

finopsway-costs browser extension. Last updated 12 August 2026.

The Chrome Web Store and addons.mozilla.org require a privacy policy at a public URL for any extension that handles authentication information. This page is that policy, and it describes the extension's behaviour as shipped.

The short version

The extension has no backend. Nothing it reads leaves your browser, except to go back to the Databricks workspace you are already signed in to. We operate no server, receive no data, and have no way to see what you query.

What the extension handles

A Databricks personal access token, if you choose token mode. It is stored with chrome.storage.local, keyed by workspace origin. That store is readable by this extension alone, is never synced to a browser account, and is cleared when you remove the token from the options page or uninstall the extension. In session mode nothing is stored: the extension reuses the workspace session you already have, and the CSRF token it needs is fetched per request and held in memory for the duration of that request.

Databricks billing usage records and SKU prices. The extension runs a read-only SQL query against the system.billing tables of your own workspace and keeps the rows in IndexedDB, in the workspace origin's own storage. This is a cache: it holds a rolling window of about a week, is pruned on every sync, and can be dropped at any time from the options page. It contains only records the signed-in identity is already entitled to read.

Extension settings. Your warehouse choice, catalog and display preferences, in chrome.storage.local.

Where data goes

Every network request the extension makes is to the Databricks workspace host you are visiting, matching *.cloud.databricks.com or *.azuredatabricks.net. There are no other hosts, and the extension declares no permission that would allow any. Your token is sent to that workspace and nowhere else. Credentials are keyed by workspace origin, so a token for one workspace is not reachable from another.

What we do not do

  • We do not collect, receive, store or transmit any of your data. There is no server to send it to.
  • We do not sell or transfer your data to third parties.
  • We do not use your data for anything unrelated to the extension's single purpose, which is displaying your Databricks spend.
  • We do not use your data to determine creditworthiness or for lending.
  • There is no analytics, telemetry, crash reporting or advertising of any kind.
  • The extension writes nothing to Databricks. Its SQL only reads system.billing.

Logging

Released builds do not write diagnostic traces to the page console. Even in a development build with tracing enabled, the access token and the CSRF token are never logged; the trace names the authentication mode only, and automated tests enforce that.

Removing your data

Uninstalling the extension removes the stored token and settings. The cached billing rows live in the workspace origin's IndexedDB and are removed by the Clear cached usage action on the options page, or by clearing site data for the workspace in your browser.

A note on token scope

A Databricks personal access token is a full-privilege workspace credential; it cannot be scoped to system.billing alone. The extension only ever issues read-only billing queries with it, but you should treat the token as you would any workspace credential: prefer a short-lived one, and revoke it in Databricks when you no longer need it. Session mode avoids storing a credential at all.
